title: "3.1 Type scale"
description: "Typography · Section 3.1"
---

A type scale is a fixed set of sizes. You pick them once and use only those.

The alternative — choosing a size per situation — produces interfaces with fourteen sizes between 13px and 19px, none of which relate to each other. It looks accidental because it is.

---

## Building one

Pick a base (usually 16px, the browser default) and a ratio. Each step multiplies:

```text
ratio 1.25 (major third), base 16px

12px   caption, labels
14px   small body, metadata
16px   body            ← base
20px   large body, small headings
24px   heading
32px   large heading
40px   display
```

Common ratios: 1.2 (subtle, good for dense UI), 1.25 (balanced), 1.333 (dramatic, good for marketing).

**Round the results.** A strict ratio gives you 16 → 20 → 25 → 31.25. Round to whole pixels; nobody can see the difference and the values become memorable.

---

## Fewer sizes than you think

Most product interfaces need five or six sizes total. If you are reaching for a seventh, check whether an existing one would do.

Consistency beats precision here. Six sizes used rigidly looks designed; eleven used approximately looks careless, even if each individual choice was defensible.

---

## As tokens

```css
--text-xs:  0.75rem;   /* 12px */
--text-sm:  0.875rem;  /* 14px */
--text-md:  1rem;      /* 16px */
--text-lg:  1.25rem;   /* 20px */
--text-xl:  1.5rem;    /* 24px */
--text-2xl: 2rem;      /* 32px */
```

Use `rem` so the scale respects the user's browser font size setting. Sizing body text in `px` overrides a real accessibility preference — people who set a larger default did so for a reason.

---

## Fluid type

For sizes that should scale with viewport, `clamp()` does it without breakpoints:

```css
--text-display: clamp(2rem, 1.5rem + 2.5vw, 3.5rem);
/*               min     preferred          max  */
```

Useful for display and hero text. Body text should generally stay fixed — it is already at a comfortable reading size, and scaling it with the viewport makes it too large on wide screens.

---

## Line height belongs to the scale

Every size needs a line height, and it is not one value:

```css
--text-sm:  0.875rem;  --leading-sm:  1.5;
--text-md:  1rem;      --leading-md:  1.5;
--text-xl:  1.5rem;    --leading-xl:  1.3;
--text-2xl: 2rem;      --leading-2xl: 1.2;
```

Line height scales **inversely** with size. Large text needs proportionally less. A 32px heading at 1.5 line height looks like it has fallen apart. Details in 3.2.
