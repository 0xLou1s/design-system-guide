Cursor's job posting asks for someone who can **prototype ideas in hours, not days.** That is not a speed requirement — it is a description of a different way of working.

Some decisions cannot be made in a design tool, because the tool cannot represent what is being decided. Prototyping in code is how those decisions get made by the person who cares about the answer.

This is where your background pays off most directly. You can already build the thing. The shift is building it *before* it has been specified, to find out what it should be.

## The mental shift

From chapter 1: the habit to break is waiting for a mockup before you start.

When you catch yourself thinking "I'll build it once design sends something," that is the moment. The role begins when you can start from the problem — sketch three versions in an afternoon, feel them, and bring the best one to the conversation.

A design engineer who can build the thing being debated, *during* the debate, ends debates.
