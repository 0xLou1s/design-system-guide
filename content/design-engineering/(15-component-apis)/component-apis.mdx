A component's API determines what is easy to build, what is hard, and what is impossible — which means it determines what the product ends up looking like.

This is the clearest place where the two halves of the role meet. API design is an engineering skill you already have. Knowing *which* API expresses the design system correctly is the design half.

## The test

A good component API makes the right thing easy and the wrong thing awkward.

If people are routinely passing `className` to override your padding, your padding is wrong. If everyone sets the same three props together, that combination should be a variant. If a prop is only ever used with one other prop, they are one prop.

Read how your components are actually used. The usage is feedback about the API, and it is more reliable than your intentions.
