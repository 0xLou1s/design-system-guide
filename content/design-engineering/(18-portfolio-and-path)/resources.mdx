---

## Design, for developers

**Refactoring UI** — Adam Wathan and Steve Schoger. One of the most efficient books on interface design, written explicitly for developers. If you read one thing, this.

**Design for Developers** — Sarah Drasner. A practical course aimed at exactly this transition.

**Awwwards Academy** — visual and creative skills from working professionals. More relevant if you are heading toward marketing work (16.1).

---

## Reading the source

Better education than most articles, and free:

```text
Radix UI      accessible behaviour, composition, escape hatches
React Aria    the most thorough accessibility implementation
Base UI       newer, clean API design
shadcn/ui     composition patterns, good API decisions
```

Read the source of a component you use often. The state handling and accessibility work in well-built primitives shows you what the problem actually is — most of it is invisible until you look.

## How to use any of this

Pick one. Work through it properly. Build something with it.

The failure mode is collecting resources as a substitute for doing the work — and it is particularly tempting in a field where reading feels like progress. Chapter 17 is the corrective: the method is repetition, not input.
