---
title: Compression
description: Brotli over gzip, on every text response.
---

Text compresses extremely well. HTML, CSS, JavaScript, JSON and SVG routinely
drop by 70–90%. Serving them uncompressed is the single easiest large win
available, and it is a server setting rather than a code change.

**Use Brotli**, falling back to gzip. Brotli is typically 15–20% smaller than
gzip on JavaScript and is supported by every current browser. Most CDNs and
hosts enable both by default — verify rather than assume.

```nginx
# nginx
brotli on;
brotli_types text/plain text/css application/javascript application/json image/svg+xml;
gzip on;
gzip_types text/plain text/css application/javascript application/json image/svg+xml;
```

Check what you are actually serving with the `content-encoding` response header:

```sh
curl -sI -H "Accept-Encoding: br,gzip" https://example.com/app.js | grep -i content-encoding
```

## Do not compress what is already compressed

Images, video, and fonts in WOFF2 are already compressed. Running gzip over them
burns CPU for roughly nothing, and can make the file marginally larger. Restrict
compression to text MIME types, as above.

## Static versus dynamic

**Static compression** compresses files once at build time and serves the
result. No per-request CPU, and you can afford the slowest, highest-ratio
setting. Use it for anything you build ahead of time.

**Dynamic compression** happens per request, for generated HTML and API
responses. Keep the level moderate — maximum Brotli on a dynamic response can
cost more time in CPU than it saves in transfer.
