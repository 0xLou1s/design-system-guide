Performance work has a failure mode: a long checklist, applied uniformly, that
makes the code worse and the page no faster. Most of the items are real, but
only a few of them matter on any given page, and you cannot tell which without
measuring first.

So this part is ordered the way the work should go. Measure, find the biggest
cost, fix that, measure again.

## The short version

Almost every slow page is slow for one of four reasons:

1. **Too many bytes**, usually images or JavaScript.
2. **Bytes arriving in the wrong order**, so the browser waits on something it
   did not need yet.
3. **Render-blocking resources**, mostly CSS and synchronous scripts.
4. **A slow server**, which no amount of frontend work will fix.

Everything below is a specific case of one of those.

## How to read this

Each page states the practice, explains the mechanism behind it, and says when
it does *not* apply. That last part matters: several of the most-repeated
performance rules were written for HTTP/1.1 and became actively wrong under
HTTP/2.
