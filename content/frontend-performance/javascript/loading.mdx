---
title: Loading
description: A plain script tag stops the parser dead.
---

When the HTML parser reaches a `<script>` without `async` or `defer`, it stops.
It fetches the script, executes it, and only then continues parsing. A script in
the `<head>` therefore blocks everything, including first paint.

```html
<!-- Blocks parsing while it fetches and runs. -->
<script src="/app.js"></script>

<!-- Fetches in parallel, runs after parsing, in document order. -->
<script src="/app.js" defer></script>

<!-- Fetches in parallel, runs as soon as it arrives, order not guaranteed. -->
<script src="/analytics.js" async></script>
```

**`defer` is the default you want.** Scripts download in parallel, execute in
order after the document is parsed, and never block rendering.

**`async` is for independent scripts** with no dependency on your code or each
other — analytics being the classic case. Execution order is whatever finishes
first, so anything with dependencies will break intermittently.

**`type="module"` is deferred automatically.** No `defer` needed.

## Inline scripts

An inline `<script>` in the body blocks the parser at that point, just like an
external one. Worse, it cannot be cached, and it is re-sent with every page.

Move logic into external files. The exception is a small snippet that genuinely
must run before paint — a theme-flash preventer reading `localStorage`, for
instance. Keep those tiny and rare.

## The real problem is total cost

`defer` stops JavaScript blocking the *parser*. It does not stop it blocking the
*main thread* once it executes.

A deferred 500kB bundle still has to be parsed, compiled and run, and on a
mid-range phone that is seconds of unresponsive page. This is what
[INP](/frontend-performance/measuring/budgets) measures, and no loading attribute fixes
it.

The fixes are structural:

**Split by route.** Ship the code for the current page, not the whole app. Every
modern bundler does this from dynamic `import()`.

**Defer non-essential work.** A chat widget, a carousel below the fold, a
cookie banner — load them on interaction or when idle, not at boot.

```js
// Load the editor only when someone actually needs it.
button.addEventListener("click", async () => {
  const { Editor } = await import("./editor.js");
  new Editor(el);
});
```

**Break up long tasks.** Anything over 50ms blocks input. Yield to the main
thread between chunks of work.
