There is a long-standing belief that selector performance matters — that
descendant selectors are slow, that you should optimize the rightmost key
selector, that ID selectors are meaningfully faster than class selectors.

On any browser from the last decade, **this is almost never measurable**. Style
recalculation is rarely the bottleneck, and browsers optimize selector matching
aggressively. Writing worse-structured CSS to chase it is a bad trade.

## What actually costs you

**Stylesheet size.** Covered in [unused CSS](/frontend-performance/css/unused-css).
This is the one that matters.

**Specificity wars.** Not a runtime cost, a maintenance one — but it becomes a
performance problem indirectly. When every override needs a more specific
selector, the stylesheet only grows, and nobody dares delete anything because
they cannot tell what depends on it.

**Layout thrashing.** Reading a layout property (`offsetHeight`, `getBoundingClientRect`)
right after writing one forces a synchronous reflow. In a loop, this is
genuinely slow — and it is JavaScript's fault, not CSS's.

```js
// Forces a reflow on every iteration.
for (const el of items) {
  el.style.height = `${el.offsetHeight * 2}px`;
}

// Read everything, then write everything.
const heights = items.map((el) => el.offsetHeight);
items.forEach((el, i) => { el.style.height = `${heights[i] * 2}px`; });
```

**Expensive properties on animation.** Animating anything that triggers layout —
`width`, `height`, `top`, `left` — costs a reflow per frame. Animate `transform`
and `opacity`, which the compositor handles without touching layout.

## Worth tracking anyway

Stylesheet statistics are useful as a trend rather than a score. A steadily
climbing rule count or specificity graph tells you the CSS is accumulating
rather than being maintained.

- [CSS Stats](https://cssstats.com/)
- [Project Wallace](https://www.projectwallace.com/) — the same, tracked over time
- [Avoid large, complex layouts and layout thrashing](https://web.dev/articles/avoid-large-complex-layouts-and-layout-thrashing)
