---
title: Minification
description: Free bytes, from a build step you configure once.
---

Minifying CSS removes comments, whitespace and redundant syntax, and can merge
duplicate rules. Typical saving is 10–25% before compression.

Because [gzip and Brotli](/frontend-performance/server/compression) compress repeated
text well, the saving *after* compression is smaller — but it is still real, and
it costs nothing to keep on.

```js
// postcss.config.js
export default {
  plugins: {
    cssnano: process.env.NODE_ENV === "production" ? {} : false,
  },
};
```

[cssnano](https://cssnano.github.io/cssnano/) and
[Lightning CSS](https://lightningcss.dev/) are the common choices. Most build
tools include one already — Vite minifies CSS in production by default.

## Concatenation is no longer the default answer

Older advice says to concatenate all stylesheets into one file. Under HTTP/1.1
that was right, for [the reasons described here](/frontend-performance/html/requests).

Under HTTP/2 it is a trade-off rather than a win. One big file invalidates
entirely when any rule changes; several smaller files let unchanged ones stay
cached. Split along lines that change at different rates — a stable framework
layer and a volatile application layer — rather than bundling everything or
splitting arbitrarily.
