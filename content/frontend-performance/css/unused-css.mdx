---
title: Unused CSS
description: Most stylesheets ship far more rules than any page uses.
---

A typical site using a CSS framework ships a stylesheet where the majority of
rules never match anything. Every unused rule costs download time, parse time,
and — because the browser builds a lookup structure from all of it — a little
matching time too.

## Find it

The Coverage panel in Chrome DevTools records which rules actually ran during a
session. Open it, record, click around the page, and it reports unused bytes per
file.

Read the result carefully. "Unused" means *not used during this recording*. A
modal's styles look unused until someone opens the modal. Coverage tells you
where to look, not what to delete.

## Remove it

**At build time.** [PurgeCSS](https://github.com/FullHuman/purgecss) scans your
templates for class names and drops rules that never appear. Tailwind and most
modern CSS frameworks do this by default — if you are using one, this is already
handled.

The failure mode is dynamically constructed class names:

```js
// PurgeCSS cannot see this; the class gets stripped.
const cls = `text-${color}-500`;

// It can see this.
const cls = { red: "text-red-500", blue: "text-blue-500" }[color];
```

**At the source.** Deleting dead CSS by hand is safer than it sounds if the
codebase uses scoped styles — CSS modules, single-file components, or
CSS-in-JS. When styles live next to the component they style, an unused
component takes its CSS with it when deleted.

This is the real fix. Tooling that strips unused rules is a workaround for
stylesheets that are not scoped in the first place.

## Check your reset

Before adding a normalize or reset file, check whether your framework already
includes one. Shipping two is common and entirely wasted.

- [Chrome DevTools Coverage](https://developer.chrome.com/docs/devtools/coverage)
- [PurgeCSS](https://github.com/FullHuman/purgecss)
