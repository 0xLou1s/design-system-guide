## Overview

Great interfaces start with shared decisions. A design system brings those decisions together, so every screen feels like part of the same product.

This sample page introduces the building blocks: **foundations**, **tokens**, and **components**.

<Callout title="Start with the essentials">
  Define a small set of foundations, connect them to reusable components, and refine them in a real interface.
</Callout>

## Foundations

Foundations give your product a consistent visual language. Start with clear roles for color, typography, spacing, and motion.

| Foundation | Purpose | Example |
| --- | --- | --- |
| Color | Communicate meaning and hierarchy | Primary, surface, muted |
| Typography | Make content easy to navigate | Heading, body, caption |
| Spacing | Establish rhythm and relationships | 4, 8, 12, 16, 24 |
| Motion | Explain changes in the interface | Focus, feedback, transitions |

### Design principles

- **Clarity:** make the next action easy to understand.
- **Consistency:** use familiar patterns across the product.
- **Accessibility:** consider different ways people interact.
- **Purpose:** give every visual decision a reason.

## Design tokens

Tokens give shared decisions a name. Use semantic names to describe a value's role in the interface.

<Tabs items={["CSS", "TypeScript"]}>
  <Tab value="CSS">
    ```css title="tokens.css"
    :root {
      --color-primary: #171717;
      --color-surface: #ffffff;
      --space-control: 0.75rem;
      --radius-control: 0.35rem;
    }

    .dark {
      --color-primary: #fafafa;
      --color-surface: #0d0d0d;
    }
    ```
  </Tab>
  <Tab value="TypeScript">
    ```ts title="tokens.ts"
    export const tokens = {
      color: {
        primary: "var(--color-primary)",
        surface: "var(--color-surface)",
      },
      space: { control: "var(--space-control)" },
      radius: { control: "var(--radius-control)" },
    } as const;
    ```
  </Tab>
</Tabs>

### Naming conventions

Prefer names such as `color.text.muted` and `color.action.primary`. A role-based name stays useful when the underlying value changes.

## Components

Components turn foundations into reusable interface elements. Each component should document its purpose, variants, states, and keyboard behavior.

```tsx title="save-button.tsx"
export function SaveButton() {
  return (
    <button type="submit" className="save-button">
      Save changes
    </button>
  );
}
```

<Callout type="warn" title="Document every state">
  Consider loading, disabled, focus, and error states alongside the default appearance.
</Callout>
